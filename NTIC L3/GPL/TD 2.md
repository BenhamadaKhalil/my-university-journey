# **📘 TD 2 — Project Management**

## **Exercise 1**

### **Project Context:**

University mobile application for timetables, grades and notifications.

### **1) Identify the elements**

|Element|Answer|
|---|---|
|**Project Objective**|Develop a mobile application that allows students to view timetables, grades, and receive notifications.|
|**Time Constraint**|The project must be completed **before the next academic year begins**.|
|**Human Resources**|3 developers, 1 project manager, 1 graphic designer.|
|**Technical Constraints**|The application must be **compatible with both Android and iOS**.|

---

### **2) Why is this an IT project?**

Because it involves:

- Developing **software** using information technologies (mobile development),
    
- Requires **planning**, **resources**, **tools**, and **deadlines**,
    
- Produces a **digital deliverable** (mobile app).
    

---

### **3) Roles involved**

|Role|Responsibility|
|---|---|
|**Project Manager**|Coordinates the team, planning, follow-up.|
|**Developers**|Write and test the application code.|
|**Graphic Designer**|Creates the UI/UX design for the app.|
|**University Administration (Client)**|Defines needs and validates results.|

## **Exercise 3**

### **Context:** Stock management software following the waterfall model.

### **1) Order of project steps (Waterfall Lifecycle)**

1. **Requirements Analysis** (define needs with store manager)
    
2. **Specification** (analysts write requirements document)
    
3. **Design** (database structure + interfaces)
    
4. **Implementation (Development)**
    
5. **Testing**
    
6. **Deployment/Installation**
    
7. **Maintenance and follow-up**
    

---

### **2) Deliverables**

|Step|Deliverable|
|---|---|
|Requirements Analysis|Needs description / Interviews summary|
|Specification|Requirements document (Cahier des Charges)|
|Design|Database schema + UI design documents|
|Implementation|Source code / Executable application|
|Testing|Test reports|
|Deployment|Installed system, user guides|
|Maintenance|Updates and support logs|

---

### **3) Phase before these steps in the Spiral Model**

→ **Risk Analysis / Feasibility Study**

This phase identifies technical, financial, and operational risks.

---

## **Exercise 4**

### **Context:** Web application for train ticket booking.

### **1) Main problems**

- Communication difficulties within the team.
    
- Poor integration between modules.
    
- Developer leaving → delays.
    

---

### **2) Type of problems**

|Problem|Type|
|---|---|
|Communication issues|**Human / Organizational**|
|Integration issues|**Technical / Organizational**|
|Team member leaving → delays|**Human**|

---

### **3) Actions to reduce difficulties**

✅ **Improve communication** → hold regular team meetings / daily stand-ups  
✅ **Use collaborative tools** → Git, Trello, Slack  
✅ **Define integration standards** → shared coding rules, API contracts  
✅ **Ensure knowledge sharing** → documentation to avoid dependency on individuals

**(Any two of these are acceptable in an exam.)**
