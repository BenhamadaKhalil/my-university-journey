# 🎯 **Lesson 2 — Characteristics of an IT Project

## 💡 What Is an IT Project?

An **IT Project** is a **temporary and unique set of coordinated activities** aimed at **building, improving, or maintaining an information system**.

An IT project must:

- 🎯 Achieve a **clearly defined objective**
    
- ⏱️ Respect **deadlines**
    
- 💰 Stay within an **approved budget**
    
- 👥 Use **human and material resources** efficiently
    
- ✅ Deliver the **required quality**
    

📌 IT projects are **complex** because they involve **technology + people + organization**.

### 👥 Typical Actors Involved

- 👨‍💻 Developers
    
- 👨‍🏫 Project Manager
    
- 🧑‍💼 Client / Users
    
- 🛠 Technicians / Support staff
    

---

## 🔁 IT Project Life Cycle

An IT project evolves through **structured phases**, from idea to closure.

| Phase                              | Purpose                                                     | Main Output                    |
| ---------------------------------- | ----------------------------------------------------------- | ------------------------------ |
| **1. IDEA** 💭                     | Identify a problem or opportunity                           | Initial concept                |
| **2. PRE-PROJECT** 🔍              | Feasibility (technical, economic, time) + solution analysis | Preliminary study              |
| **3. PROJECT REQUEST** 📝          | Formal decision to start + budget approval + PM appointment | Project approval               |
| **4. INITIATION** 🚀               | Define scope, risks, roles, organization, communication     | Project Charter                |
| **5. PLANNING** 📅                 | WBS, estimates, schedules (GANTT/PERT), risk planning       | Project Plan                   |
| **6. EXECUTION & MONITORING** ⚙️📊 | Perform tasks + control progress vs plan                    | Deliverables + Status reports  |
| **7. CLOSURE** ✅                   | Delivery, evaluation, documentation, release resources      | Final report + Lessons learned |

📌 **Key rule:**  
👉 Planning without monitoring = loss of control ❌

---

## 🔗 Project Phases vs Software Development Phases

Each project phase corresponds to **one or more software phases**.

| Project Phase          | Software Phase                    |
| ---------------------- | --------------------------------- |
| Initiation             | Requirements Analysis 📝          |
| Planning               | System Design 🧩                  |
| Execution & Monitoring | Implementation 👨‍💻 + Testing 🧪 |
| Closure                | Deployment 🚀 + Maintenance 🔧    |

---

## 🛠 Software Development Steps

| Step                            | Objective                                       | Deliverable                      |
| ------------------------------- | ----------------------------------------------- | -------------------------------- |
| **Requirements Analysis** 📝    | Understand client needs                         | Requirements specification       |
| **System Design** 🧩            | Define architecture, models, database           | Design document                  |
| **Implementation** 👨‍💻        | Develop and integrate code                      | Source code                      |
| **Testing** 🧪                  | Verify functional & non-functional requirements | Test reports                     |
| **Deployment & Maintenance** 🚀 | Deliver, support, fix, evolve system            | Final release + maintenance plan |

📌 Most software cost occurs **after deployment** (maintenance).

---

## 🏛 Project Leadership vs Project Management

These are **two complementary responsibility levels**.

| Level                                      | Role                       | Focus                                           |
| ------------------------------------------ | -------------------------- | ----------------------------------------------- |
| **Project Leadership (Strategic)** 🧭      | Steering & decision-making | Vision, objectives, alignment, validation       |
| **Project Management (Operational)** 🧑‍💼 | Planning & execution       | Scheduling, resources, risks, costs, monitoring |

📌 **Leadership = “WHAT & WHY”**  
📌 **Management = “HOW & WHEN”**

---

## ⚠️ Challenges in IT Projects

IT projects are **difficult to control** because of:

- 🗣️ Communication complexity
    
- 🔄 Changing requirements
    
- 🧪 Technical uncertainty
    
- ❤️‍🔥 Human motivation and coordination
    

### 📐 Communication Law (Brooks)

For **n team members**:

```
Communication channels = n(n − 1) / 2
```

📌 More people → more communication → more management effort  
📌 Adding people late can delay the project ❌

---

## 🧱 Project Development Models

### 1️⃣ Linear / Waterfall Model 💧

- Sequential phases
    
- Each phase produces a document
    
- Reviews at each step
    
- Best when requirements are **stable**
    

⚠️ Weak against change

---

### 2️⃣ Spiral Model (Boehm) 🌀

- Iterative and **risk-driven**
    
- Regular risk evaluation
    
- Combines:
    
    - Waterfall (for structure)
        
    - Prototyping (for user validation)
        

✅ Well-suited for **large, complex, evolving IT projects**

---

## 🧰 Standards, Methods & Frameworks

To deliver quality software **on time and within budget**, organizations rely on:

- 📚 **Methods & frameworks** (PMBOK, Agile, Scrum…)
    
- 🧩 **Tools** (UML, Git, Jira…)
    
- ✅ **Quality practices** (reviews, testing, documentation)
    

They cover both:

- Software production (analysis → testing)
    
- Project control (planning → monitoring)
    

---

## ✅ Final Lesson Takeaways 🧠

- IT projects are **unique, complex, and human-centric**
    
- Requirements evolve continuously
    
- Planning alone is not enough → **monitoring is critical**
    
- Leadership and management serve **different but complementary roles**
    
- Communication and coordination are key success factors
    

> 🧠 **Projects fail because of poor planning and communication —  
> they succeed through structure, leadership, and continuous control.**
